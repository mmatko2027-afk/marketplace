# ClickBack

## Опис проєкту

**ClickBack** — REST API платформи оголошень для купівлі та продажу електроніки. Система призначена для розміщення оголошень, перегляду товарів, пошуку необхідної техніки та взаємодії між користувачами.

Проєкт розробляється на платформі ASP.NET Core із використанням мови програмування C#. Для зберігання даних використовується SQLite, а Entity Framework Core забезпечує взаємодію між програмою та базою даних.

Основна мета ClickBack — створити зручну серверну частину маркетплейсу, яка забезпечує керування користувачами, товарами, категоріями та іншими даними платформи.

## Основні можливості

### 1. Користувачі (`User`)

Система передбачає реєстрацію та автентифікацію користувачів. Для кожного користувача зберігається необхідна інформація, зокрема ім'я, електронна пошта та дані для входу.

Передбачена рольова модель доступу, яка дає змогу розмежовувати права звичайних користувачів та адміністраторів.

### 2. Категорії (`Category`)

Категорії використовуються для групування оголошень за типами електроніки. Це спрощує пошук товарів і допомагає користувачам швидше знаходити потрібну продукцію.

### 3. Оголошення (`Listing`)

Оголошення містять інформацію про товари, які користувачі пропонують для продажу.

Основні дані оголошення:
- назва товару;
- опис;
- ціна;
- категорія;
- інформація про користувача, який створив оголошення.

API передбачає створення, перегляд, редагування та видалення оголошень відповідно до реалізованих методів і прав доступу.

### 4. Обране (`Favorite`)

Функціональність обраного дає змогу користувачам зберігати оголошення, які їх зацікавили, щоб швидко повертатися до них пізніше.

Для цього використовується зв'язок між користувачами та оголошеннями.

### 5. Повідомлення (`Message`)

Модель повідомлень призначена для зберігання інформації про спілкування між користувачами платформи. Вона може використовуватися для реалізації обміну повідомленнями щодо товарів та умов їх придбання.

## Робота з оголошеннями

API забезпечує роботу з оголошеннями через HTTP-запити. Залежно від реалізованих ендпоїнтів користувачі можуть отримувати список товарів, переглядати окремі оголошення, створювати нові та змінювати наявні.

Також передбачена можливість розширення механізму пошуку за такими параметрами:
- назва товару;
- категорія;
- ціновий діапазон;
- інші характеристики оголошення.

Для зручної роботи з великою кількістю товарів можуть використовуватися фільтрація, сортування та посторінкове виведення результатів.

Під час обробки запитів враховуються зв'язки між оголошеннями, категоріями та користувачами.

## Авторизація та безпека

Для захисту API використовується механізм автентифікації на основі JWT (JSON Web Token).

Після успішного входу користувач отримує токен, який передається в заголовку `Authorization` під час звернення до захищених ендпоїнтів.

JWT дає змогу:
- перевіряти особу користувача;
- обмежувати доступ до захищених операцій;
- розмежовувати права користувачів за ролями;
- захищати адміністративні функції.

## Інтеграції із зовнішніми сервісами

Проєкт передбачає можливість взаємодії із зовнішніми API для розширення функціональності маркетплейсу.

### Нова пошта

Інтеграція з API Нової пошти призначена для отримання інформації про населені пункти та відділення доставки.

Це дає змогу використовувати актуальні дані служби доставки під час організації відправлення товарів.

### AI-помічник

У проєкті передбачено AI-помічника, який використовує зовнішню мовну модель для обробки запитань користувачів.

Його призначення — допомагати з питаннями щодо роботи маркетплейсу, пошуку товарів та основних можливостей платформи. Можливості доступу до даних оголошень і замовлень залежать від реалізованих механізмів взаємодії AI-помічника з API та базою даних.

## Архітектура проєкту

ClickBack має багаторівневу архітектуру, яка розділяє відповідальність між основними частинами застосунку.

### `Marketplace.Api`

Рівень взаємодії із зовнішніми клієнтами. Містить контролери, HTTP-ендпоїнти, налаштування автентифікації та конфігурацію застосунку.

Його основне завдання — приймати HTTP-запити, передавати їх на відповідну обробку та повертати клієнту результат.

### `Marketplace.Application`

Рівень прикладної логіки. Містить сервіси та компоненти, які реалізують основні сценарії роботи системи.

Він відповідає за обробку операцій, пов'язаних із користувачами, оголошеннями та іншими функціями маркетплейсу.

### `Marketplace.Domain`

Рівень предметної області. Містить основні сутності та правила, які описують предметну область системи.

До основних сутностей належать:
- `User`;
- `Category`;
- `Listing`;
- `Favorite`;
- `Message`.

### `Marketplace.Infrastructure`

Інфраструктурний рівень. Відповідає за роботу з базою даних, реалізацію доступу до даних, налаштування Entity Framework Core та взаємодію з інфраструктурними компонентами.

## Документація та тестування API

Для перегляду доступних ендпоїнтів і тестування HTTP-запитів використовується Swagger UI.

Swagger дає змогу:
- переглядати доступні контролери та методи;
- ознайомлюватися з параметрами запитів;
- надсилати GET, POST, PUT і DELETE-запити;
- перевіряти відповіді сервера;
- тестувати захищені ендпоїнти за допомогою JWT.

## Запуск проєкту

Для запуску необхідно мати встановлений .NET 10 SDK.

1. Клонувати репозиторій:

```bash
git clone https://github.com/mmatko2027-afk/marketplace.git
```

2. Перейти до папки API:

```bash
cd marketplace/Marketplace.Api
```

3. Відновити залежності:

```bash
dotnet restore
```

4. Запустити застосунок:

```bash
dotnet run
```

Після запуску адреса Swagger UI відображається в консолі або визначається налаштуваннями запуску застосунку.

## Конфігурація та безпека даних

Налаштування застосунку зберігаються у конфігураційних файлах та змінних середовища.

Секретні значення, зокрема ключі зовнішніх API та секретний ключ JWT, не слід зберігати у відкритому вигляді в репозиторії.

Для локальної розробки можна використовувати механізм .NET User Secrets.
